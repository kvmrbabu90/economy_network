# Domino study — implementation rulings and deferred minors

Every judgement call made while building and running the pre-registered study, copied from the execution ledger (in order). Each line says what was decided, why, and what it costs if wrong. Spec-level changes are also logged in the spec's §13.

## Rulings

- Setup: Ruling: plan is task-level (no full code / per-step Expected lines) — judgement call recorded in the plan header to avoid writing ~2k lines twice; per-step Expected = "tests pass" — cost if wrong: less mechanical steps, mitigated by TDD + final review.
- Setup: Ruling: manual `git worktree add` outside OneDrive instead of the native EnterWorktree tool — native tool requires an explicit "worktree" request, a git-repo session folder, and branches fresh; the scheduler runs from the main checkout, which must stay on main — cost if wrong: a worktree the harness doesn't track (remove manually at finish).
- (missing) fetch stages -> T3: plan's file table lists fetch_prices.py/fetch_factors.py but no task builds them. Ruling: build both inside Task 2 ("data snapshot stages") with an injectable downloader so tests never hit the network — spec §3/§10 require them — cost if wrong: Task 2 is larger.
- T3 returns -> T4,T5,T8 robustness 1/2/3: Ruling: returns model takes a ModelSpec {market | sector_etf | ff6} so shocks+events+measure re-run per variant (spec §8 changes the AR definition everywhere, incl. shock detection) — cost if wrong: variants recompute more than strictly needed.
- T3 returns -> T5 controls + T4/H6: Ruling: T3 also exposes dollar-volume [-80,-21] (>=20 valid days) and abnormal-volume helpers from prices.volume — spec §4 + §13.5/§13.7.
- T5 events -> T8 placebo: Ruling: T5 exposes a pure build_events_for_links(shocks, links, ...) reused by the placebo with random links — spec §5 placebo rebuilds events for random pairs.
- Task 2: Ruling: US-style ticker only, '.'->'-' only for one-letter share classes; foreign-only 300750.SZ excluded (universe 572) — plan's blanket '.'->'-' would break exchange suffixes and a non-synchronous listing fakes next-day ripples; logged spec §13.12 before data — cost if wrong: one firm dropped.
- Task 3: Ruling: build_panel copies arrays (to_numpy copy=True) — pandas 3 copy-on-write returns read-only views; a frozen array is a trap for later stages — cost if wrong: ~2x panel memory (MBs).
- Task 3: Ruling: robustness-1 'sector_etf' model = plain excess return d = r_i - r_ETF (no estimated params); sigma = sample std (ddof 1) of d over [e-270,e-21]; firm usable only with >=200 valid days — spec §8.1 says "excess return instead of the market model" with no estimator, so none is added — cost if wrong: robustness-1 shock threshold scale differs slightly from a mean-adjusted variant.
- Task 3: Ruling: SPY itself gets no market model (y == x is degenerate, sigma 0) — it is the market, never a firm — cost if wrong: none.
- Task 3: Ruling: fixed own test before implementing: blanking [e-80,e-41) leaves 21 valid days, not 19; now blanks 41 rows so the <20-day rule is actually exercised.
- Task 4: Ruling: robustness-3 '4 sigma' is a full re-detection (dedup among 4-sigma candidates only), not a subset of 3-sigma events — §8.3 changes the shock definition; a 3-4 sigma day must not suppress a later 4-sigma shock — cost if wrong: slightly different 4-sigma event set; plan said "subset" (superseded).
- Task 4: Ruling: sector_etf_z (robustness 5) always uses the ETF's MARKET model; NaN under the non-market variants — §13.9 defines it via the ETF's market-model AR — cost if wrong: robustness 5 only reported for the primary model.
- Task 4: Ruling: top-1% threshold is computed from study-period (2015+) values per firm (§13.10); pre-2015 candidates still take part in dedup so a late-2014 shock can suppress an early-2015 one, same as the primary rule — cost if wrong: a handful of boundary events.
- Task 5: Ruling: an event also needs B to have a valid dollar volume (>=20 days) — controls are ranked by distance to log DV(B), which is undefined otherwise; spec §4 implies it — cost if wrong: a few events with thin B volume history dropped.
- Task 5: Ruling: holdout gate enforced twice (stage entry AND build_events_for_links) — defense in depth so no code path, including the placebo, can build holdout events while locked — cost if wrong: tests of holdout paths must write a real-commit marker.
- Task 5: Ruling: added research/dominoes/context.py (shared panel+model loader per variant) and config.variant_suffix — one derivation path for every stage — not in the plan's file table — cost if wrong: one extra small module.
- Task 6: Ruling: plan's Holm example was arithmetically wrong ([0.001,0.01,0.04] at a=0.05 rejects all three: thresholds a/3,a/2,a/1); tests use correct cases — cost if wrong: none (textbook Holm).
- Task 6: Ruling: plan said singleton-cluster CR1 SE = iid SE x sqrt(G/(G-1)); true only vs a ddof=0 SD — against the usual ddof=1 SE they are equal; test asserts the equality — cost if wrong: none.
- Task 6: Ruling: CR1 for OLS uses Stata's G/(G-1)*(n-1)/(n-k); reduces to clustered_mean's G/(G-1) at k=1 so the mean and the slope share one convention — cost if wrong: gamma SEs differ by (n-1)/(n-2) ~ 1.
- Task 7: Ruling: detection threshold = max(3, Holm rank-1 t for the 9-test H2 family at df=G-1) — spec §5 says power under "the full pass rule"; in exploration that is Holm + |t|>3, and a lone test passes Holm only at rank 1 — cost if wrong: MDE slightly conservative when G is small.
- Task 7: Ruling: MDEs are reported in units of the injected 20-day ripple for every window (w5 sees a 5/20 share) — keeps one comparable number per role; underpowered decided on w20 bootstrap MDE as §5 states — cost if wrong: none (analytic MDE also reported).
- Task 8: Ruling: H3 pre-trend is evaluated in exploration (flag) and again in holdout; a role's H3 is "ok" only if both periods have |t_pre|<2 — §6 names no period; checking both is stricter — cost if wrong: a holdout-only pre-trend could flag a role the spec would have let through.
- Task 8: Ruling: robustness 5 (ex industry shocks) KEEPS events whose sector_etf_z is NaN (no ETF model) rather than dropping them — dropping would silently shrink the subset for reasons unrelated to industry shocks — cost if wrong: a few events with unknown sector moves remain in r5.

- Task 8: Ruling: gamma regresses the UNSIGNED ripple (s * signed ripple) on A's day-0 AR, clustered by date, windows d0/w5/w20/w60 — transmission is about magnitude and sign carried through; signed ripple vs signed AR would be identical up to sign of x — cost if wrong: none (equivalent parametrization).
